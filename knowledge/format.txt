THE GENE FILE FORMAT (format 2)
===============================
One file per locus: genes/<id>.json. UTF-8 JSON, nothing else. Any language with a JSON
parser can read it. No field depends on a game, an engine or a programming language.

This format was laid out by the exporting session on 2026-10-12 and has not been reviewed
by the owner. Change it if it is wrong, bump "format", and say so in the session log.

FIELDS
------
format        integer. 2. (Format 2, 2026-10-12, added "quality" on every allele and
              "verified" on every citation, both required.)
id            the locus id, lower case with underscores. The file name without .json.
species       "horse".
name          a readable name.
symbol        the gene symbol (MC1R, KIT) or null. null for every abstraction.
chromosome    optional. The horse chromosome the locus is on: "1" to "31", "X" or "Y".
              Left out where no source has been read for it, and on every abstraction.
              (Added 2026-10-12. An optional field, so "format" stays 1.)
evidence      "published" or "abstracted". See EVIDENCE below.
summary       one to three sentences on what the locus does.
inheritance   "autosomal", "x_linked" or "y_linked".
affects_coat  true if any genotype changes coat colour or pattern.

alleles       list, IN A FIXED ORDER that must never be changed (append only).
  id            the allele's short token, unique within the locus ("E", "e", "W20").
  name          a readable name.
  wild_type     true for the one allele that is the population's ordinary copy.
  quality       how far to trust that this allele is real. One of:
                "verified"    a maintainer opened a cited source and it describes this
                              allele.
                "unverified"  believed real, from research or from the first export, but
                              no maintainer has opened a source for it. The default.
                "abstracted"  invented, as every allele of an abstracted locus is.
                "invalid"     looked for and not found: no source supports it. It is
                              kept ON PURPOSE, so that the id is never reused and nobody
                              adds it back thinking it was overlooked. A consumer should
                              not create horses with it.
                The placeholder "Y" carries none.
  placeholder   present only on the stand-in "Y" of an x_linked locus: the missing second
                copy in a male.

phenotypes    list of the outcomes this locus can produce.
  id, name, description
  documented    optional. false marks an outcome that stands for "nobody has described
                this pair". Allowed only on a pair with an allele the mod lacks
                (mod-map.json, "not_in_mod"), or on a pair mod-map.json names under
                "mod_outcome_unsupported": a pair of two alleles the mod has always has
                an outcome there, and must not quietly lose it here.
  changes_coat  false means this outcome paints nothing on the coat. It does NOT mean
                "healthy" or "normal": every outcome of a non-coat locus is false.

genotypes     list covering EVERY pair of alleles that can exist, each exactly once.
  alleles       two allele ids. Order within the pair carries no meaning.
  phenotype     a phenotype id.
  conditions    optional list of condition ids this genotype causes.

nonviable_genotypes   optional. Pairs that cannot exist in a living horse (an embryo with
                      this pair does not develop). They are absent from "genotypes".
                      A row may carry "phenotype": what the pair would have been.

conditions    optional list of health conditions.
  id, name, description
  severity      "informational", "impairing", "lethal_in_early_life" (born alive, dies in
                its first weeks or months), "lethal_at_birth", "lethal_at_conception".

interactions  optional. Present when the outcome depends on other loci.
  depends_on    list of locus ids.
  table         every combination: "alleles" at this locus, "with" the pairs at the other
                loci, and the resulting "phenotype". Where present it overrides
                "genotypes", which then shows the outcome with the other loci at wild type.

frequencies   list of genotype frequency tables. May be empty: no frequency is known.
  population    who the table describes ("general population", "mares").
  evidence      "published" or "estimated".
  genotypes     alleles + percent. Percents in a table sum to 100. A pair not listed is 0.

citations     list.
  source        "ucdavis-vgl", "omia", "pubmed", "paper" or "other".
  label         short text.
  url
  verified      true once a maintainer has opened the address and found it says what it
                is cited for. false until then - which is nearly all of them.

EVIDENCE
--------
published    A cited source says so. On a locus: the locus is real and identified.
estimated    A number of ours for something real. Used on frequencies. EVERY frequency in
             the first export is estimated: they were tuned for a game.
abstracted   A stand-in of ours for something real that is polygenic or not understood.
             The alleles are invented. Never present an abstracted locus as a real gene.

RULES A CHANGE MUST KEEP  (tools/validate.mjs checks 2 to 5)
------------------------------------------------------------
1. Never reorder, rename or remove an allele. Append new ones at the end of the list.
   Consumers store horses by allele id, and one of them aligns stored data by order.
2. Never rename a locus id without updating mod-map.json in the same change.
3. "genotypes" plus "nonviable_genotypes" must cover every unordered pair of alleles
   exactly once (for an x_linked locus: every pair a mare or a stallion can have).
4. Every phenotype and condition id used must be declared; every declared one used.
5. Evidence is never left out and never defaulted.
6. A "published" claim needs a citation in the same change.

BREEDS (format 1, a draft)
--------------------------
One file per natural breed: breeds/<id>.json. Written by the session that exported the
mod's breeds on 2026-10-14 (knowledge/how-this-was-exported/export-breeds.mjs). The owner
has not reviewed it; every field name is the session's choice.

format        integer. 1.
id            the breed id, lower case with underscores, the same as the mod's. The file
              name without .json.
species       "horse".
name          a readable name.
country       the country of origin, as the mod writes it ("saudi_arabia"). Not yet a
              standard code.
description   optional. A sentence or two; only five breeds have one.
scores        the mod's 1-10 scores, which are not measurements. "evidence" is always
              "abstracted". "speed", "jump", "health" and "pull" are each a number, or
              [low, high] where the mod gives a range.
pools         the breed's gene pools, one per locus it has one at. A locus with no pool
              here is at its usual frequency (the gene file's tables).
  locus         a locus id from genes/.
  evidence      "estimated" (a number of the mod's) or "published" (from a cited survey).
  genotypes     alleles + percent, as in a gene file's frequency table. Each pair must be a
                genotype of the locus. Percents sum to 100.
strains       optional. Named lines within a breed whose pools differ at some loci.
  name          a readable name.
  share         the percent of the breed in this strain. Shares sum to 100.
  pools         as above. At each locus a strain lists, its pool replaces the breed's for
                horses of that strain; at every other locus the breed's pool applies.
citations     list, as in a gene file. Empty for every breed so far.

Left out of the mod's breed files on purpose: magical breeds, biomes and spawn rules,
prices, "commonness" (how often the game spawns it), the body-size model scale (not a
height), the heat- and cold-tolerance pools, and the free-text "notes", which mix facts
with notes about the game and have not been sorted.

mod-map.json
------------
Not part of the science. One row per locus: "locus" (the id here), "mod_key" (the key the
mod saves), "mod_allele_order" (the order the mod requires), "mod_only_alleles" (alleles
the mod has that this data deliberately leaves out), and "not_in_mod" (alleles this data
has that the mod lacks; they come after the mod's own in the allele list). A row may also
carry "mod_outcome_unsupported": pairs for which the mod has an outcome that no source
supports, and which are marked undocumented here on purpose.
